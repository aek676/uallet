# AGENTS.md

Turborepo + **aube** monorepo for a Solana (devnet) campus wallet. The READMEs
(root, `apps/wallet`, `apps/merchant`, `apps/api`, `packages/*`) are detailed
and current: read the relevant one before changing behaviour, and update it
when you change what it describes. `docs/overview.md` (purpose, roadmap) and
`docs/architecture.md` (payment flow, design decisions) give the big picture.

## Commands

Use `aube` to install and run scripts (never npm/pnpm/npx, nor `bun install`,
`bun add` or `bunx`). Run binaries as `aube exec <bin>`: aube supplies the Node
pinned in `devEngines`, which may be newer than `node` on `PATH`. Bun (1.4.x)
is only the runtime of `apps/api`: its `dev` script runs `bun`, which must be
on `PATH`. Its tests run under Node (Vitest), like the rest.

| Goal                           | Command                                                                     |
| ------------------------------ | --------------------------------------------------------------------------- |
| Format check / fix             | `aube run format` / `aube run format:fix`                                   |
| Lint + type-check, all         | `aube run lint`                                                             |
| Lint + type-check, one package | `aube exec turbo run lint --filter=wallet`                                  |
| Tests, all / one package       | `aube run test` / `aube run test --filter @repo/payments`                   |
| One test file                  | `aube run test --filter wallet src/features/pay/utils/payment-link.test.ts` |
| Package boundaries             | `aube exec turbo boundaries`                                                |
| Build without secrets          | `APP_ENV=test aube run build`                                               |

- There is no `tsc` or `typecheck` script. Type errors come from
  `oxlint --type-aware --type-check`, i.e. `lint`.
- `aube run <script> --filter <pkg>` is aube's filter, not Turborepo's: it runs
  the script directly in that workspace and forwards extra args. Fine for
  `test` and `dev`; for `lint` it skips `codegen`, so use the `turbo run` form.
- CI runs format, lint, boundaries, build and test. Before finishing:
  `aube run format:fix && aube run lint && aube run test`.
- Workspaces: `wallet`, `merchant`, `api`, `@repo/payments`, `@repo/i18n`,
  `@repo/ui`, `@repo/oxlint-config`, `@repo/typescript-config`. Packages have no
  build step: apps import their TypeScript source.

## Environment (Varlock)

- Never read or edit `.env.local` files (root and `apps/*`). Read
  `.env.schema`, or run `aube exec varlock load` (secrets masked).
- `APP_ENV=development` (the default) fetches values from Infisical: it needs
  the user's client secret and network. `dev`, plain `vite build` and a bare
  `vitest` in an app all use it. `APP_ENV=test` loads the committed `.env.test`
  placeholders; the `test` and `codegen` scripts already set it.
- New variable: declare it in the app's `.env.schema` and add a placeholder to
  its `.env.test`. The real value goes in Infisical (ask the user).
- Read variables through `#/config/env`. In `src/config/env.ts` the import from
  `varlock/env` must stay named `ENV`: the Vite plugin rewrites the literal
  text `ENV.<KEY>`.
- Every `VITE_*` value ends up in the browser bundle.
- `apps/api` has no Vite: `src/index.ts` imports `varlock/auto-load` first, and
  its `bunfig.toml` turns off Bun's own `.env` loading. Its variables are
  server-only: never name them `VITE_*`.

## Generated files

- `apps/*/env.d.ts` and `apps/*/src/paraglide/**` are git-ignored. On a fresh
  clone, `#/paraglide/*` and `ENV` fail type-checking until
  `aube exec turbo run codegen` (which `aube run lint` runs first).
- `apps/*/src/app/route-tree.gen.ts` is committed and generated by TanStack
  Router's Vite plugin on `dev` and `build`. Don't edit it; after adding or
  renaming a route file, regenerate it and commit it.

## Code conventions (lint-enforced)

- `wallet` and `merchant` follow bulletproof-react: shared folders
  (`components`, `config`, `hooks`, `lib`, `stores`, `utils`, `types`) ->
  `src/features/<name>` -> `src/app`. Shared code can't import features; a
  feature can't import another feature or `src/app`. Compose features in
  `src/app`.
- No `../` imports. `wallet`, `merchant` and `api` use `#/…`; `@repo/ui`
  uses `#components/*`, `#lib/*`, `#hooks/*`. Only `wallet`, `merchant` and
  `api` lint this; elsewhere it's a convention. `api` declares `#/*` twice:
  `package.json#imports` (TypeScript, Vitest) and tsconfig `paths` (Bun 1.4
  doesn't resolve `#/` imports). Keep them in sync.
- The bulletproof-react layering is for the React apps; `api` doesn't lint it.
- No barrel files. Import modules by path: `@repo/payments/<module>`,
  `@repo/ui/components/<name>`, `@repo/i18n/locales`.
- File and folder names are kebab-case.
- oxfmt sorts imports and Tailwind classes: run `format:fix`, don't hand-sort.
- Oxlint `extends` inherits only `rules`, `plugins` and `overrides`: redeclare
  `ignorePatterns` and `settings` in each workspace's `oxlint.config.ts`.

## Domain rules

- Use `PAYMENT_TOKEN` from `@repo/payments/config`, never `EURC` directly, and
  never assume the classic Token program (it will become a Token-2022 token).
  Amounts are `bigint` base units.
- `@repo/payments` has no UI and makes no network calls.
- Wallet transactions must be legacy or v0: Web3Auth's wallet can't sign v1.
- User-facing text goes through Paraglide: add the key to **both**
  `packages/i18n/messages/en.json` and `es.json` (a test fails otherwise),
  prefixed `wallet_` / `merchant_` unless every app shares it. Import `m` from
  `#/paraglide/messages.js` (with `.js`). Text built outside a render (Zod
  errors, lookup tables) must be a function, not a constant.
- Format amounts, numbers and dates with `#/lib/format`.
- `@repo/ui` is shadcn/ui on **Base UI**, not Radix. Use semantic token classes
  (`bg-primary`, `text-muted-foreground`); tokens live in
  `packages/ui/src/styles/globals.css`. Add shadcn components only from
  `packages/ui` with aube activated (root README, "Adding shadcn/ui
  components").

## Dependencies

- Most versions live in catalogs in `aube-workspace.yaml` (`catalog:<name>`);
  internal packages are `workspace:*`. Exceptions: the root tooling (`lefthook`,
  `oxfmt`, `turbo`) is pinned in the root `package.json`, and the dependencies
  shadcn added to `@repo/ui` keep their own ranges. Commit `package.json`,
  `aube-workspace.yaml` and `aube-lock.yaml` together.
- Bump `oxlint-tsgolint` together with `typescript`. `zxing-wasm` must match
  the version `barcode-detector` pins.
- The aube version is pinned twice: `devEngines` in `package.json` and
  `.github/actions/setup/action.yml`.

## Dev servers

Ports are fixed: wallet 5173 and merchant 5175 (Vite `strictPort`), api 5177
(`API_PORT` in `apps/api/.env.schema`).
`aube run dev` opens Turborepo's TUI for all apps; start one app with
`aube run dev -- --filter wallet` (through Turborepo) or
`aube run dev --filter wallet` (aube's filter, runs `vite` directly).

## Git and PRs

- Lefthook's pre-commit scans staged files for the Infisical secret, formats
  and re-stages them, runs `codegen` and lints them. Don't bypass it.
- PRs are squash-merged and the title must follow Conventional Commits, e.g.
  `feat(wallet): …` (checked in CI).
- GitHub Actions are pinned to a commit SHA with a version comment; zizmor
  audits the workflows.

## Skills

`.agents/skills/turborepo` and `.agents/skills/varlock` are committed (tracked
in `skills-lock.json`). Load them before changing `turbo.json` or env config.
